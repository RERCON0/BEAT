# Безопасность BEAT

BEAT работает с удалённым Navidrome и локальными аудиофайлами. Серверные ответы,
индекс кеша, изображения и метаданные файлов считаются недоверенными данными.

## Что защищено

- Для удалённого сервера требуется HTTPS; HTTP допускается только на loopback.
  Редиректы запросов с токеном ограничены исходным протоколом, хостом и портом.
- Пароль на Windows сохраняется с DPAPI текущего пользователя. Subsonic-токен
  `MD5(пароль + соль)` — требование протокола, а не защита хранения пароля.
  При отказе DPAPI сохранение настроек отменяется. Пароль, токен и соль удаляются
  из сообщений об ошибках до их сокращения для интерфейса.
- Ответы API, обложки, аудиозагрузки и локальные файлы состояния ограничены по
  размеру. Декодирование изображений проверяет размеры и лимит выделяемой памяти.
  Для ведущих ID3/FLAC задан суммарный предел 16 МБ; общий читатель Symphonia
  ограничивает одно объявленное бинарное поле 32 МБ до его выделения.
  [Изменение зависимости](vendor/symphonia-core/BEAT-PATCH.md) требует сохранения
  при обновлении аудиостека.
- Пути из индекса проверяются перед чтением и удалением; выход за корень кеша,
  симлинки и Windows junction отклоняются. Пользовательская музыка не очищается
  вместе с индексированными загрузками.
- Повреждённое состояние сохраняется в резервную копию. Если копию создать
  нельзя, перезапись блокируется. Ошибки чтения не превращаются в пустой кеш.
- Один экземпляр приложения на Windows предотвращает одновременное изменение
  общего состояния из нескольких сеансов.
- Индексы аудио и обложки разделены по серверу и аккаунту; сессия и история
  учитывают также папку музыки. Серверные идентификаторы не могут подменять
  идентификаторы локальных файлов.

Результаты проверки перед публикацией: [аудит от 7 октября 2026](docs/AUDIT-2026-10-07.md).

Эти проверки не заменяют права доступа Windows. Процесс под той же учётной
записью может читать файлы пользователя и использовать его DPAPI. Ошибки и
отказы самого Navidrome, аудиодрайвера или сети также остаются внешними факторами.
Декодеры выполняются внутри процесса: проверка ведущих метаданных и лимиты
изображений не заменяют изоляцию декодера и не гарантируют отсутствие ошибок
в сторонних библиотеках.

## Проверки репозитория

CI проверяет форматирование, Clippy без предупреждений, тесты и Windows x64
сборку. Отдельный Security workflow проверяет всю историю Git на секреты,
синтаксис workflows и полный Cargo.lock по RustSec ежедневно. Уязвимости,
unsound-зависимости и отозванные версии блокируют проверку.

В 0.2.1 обновлён стек egui; старый `ttf-parser 0.25.1` и связанное
предупреждение о сопровождении удалены из Cargo.lock. Полный RustSec-аудит
8 октября 2026 прошёл без advisories. Это состояние на дату проверки;
ежедневный workflow продолжает проверять новые сообщения. Совместимость
аудиостека и условие перехода на Symphonia 0.6 описаны в
[плане зависимостей](docs/DEPENDENCIES.md).

С 0.2.1 релизный ZIP подписан Ed25519: подпись покрывает манифест и хеши
исполняемого файла, README, GPL и уведомлений компонентов. Проверка использует
ключ из доверенного checkout; ключ из самого ZIP без внешнего доверия
не подтверждает издателя. [Инструкция и отпечаток ключа](docs/RELEASING.md).
Приватный ключ хранится вне репозитория и CI.

Это не Authenticode и не снимает предупреждений SmartScreen. Самостоятельный
EXE и артефакты CI не несут подпись пакета. Версия 0.2.0 остаётся неподписанной.

## Сообщить о проблеме

Свяжитесь с владельцем через [Telegram](https://t.me/rercon), указав версию,
шаги воспроизведения и ожидаемое поведение. Не публикуйте пароль, токен,
приватный адрес сервера или содержимое личной музыкальной библиотеки.
