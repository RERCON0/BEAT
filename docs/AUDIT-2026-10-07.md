# Аудит BEAT перед публикацией — 7 октября 2026

[← README](../README.md) · [Границы защиты](../SECURITY.md)

Проверены исходники приложения, сохранение данных, API Navidrome, загрузки,
локальный сканер, декодирование, интерфейс, зависимости, сборка и CI.
Исходная ревизия: `03ea923c25a0c9b14489f3da6dcc1354a47281f3`.
Подтверждённые проблемы ниже исправлены в ходе проверки. Это проверка кода
и конкретных сценариев, а не гарантия отсутствия всех возможных ошибок.

## Модель угроз

Недоверенные данные: ответы настроенного сервера, аудиофайлы и их теги,
изображения, индекс в общей папке и повреждённые файлы состояния.
Проверялось, могут ли они раскрыть учётные данные в ошибках, подменить
локальный источник, смешать данные аккаунтов, выйти за папку музыки,
потерять сохранённое состояние или вызвать чрезмерные выделения памяти.

Процесс с правами самого пользователя Windows уже имеет доступ к его файлам
и DPAPI; BEAT не создаёт дополнительную границу между такими процессами.

## Исправления безопасности и сохранности данных

| Проблема | Проверенный сценарий и результат исправления |
|---|---|
| **Смешивание аккаунтов — средняя** | На двух серверах или аккаунтах совпадает id трека либо обложки. Индексы и серверные миниатюры теперь разделены по источнику; очистка одного индекса не удаляет загрузки другого. Очередь и история также учитывают папку музыки. |
| **Частичная утечка учётных данных — средняя** | Сервер возвращает пароль, токен или соль на границе сокращаемого сообщения. Удаление секретов выполняется до сокращения текста, включая ошибки API, обложек и аудиопотока. |
| **Подмена локальных идентификаторов — средняя** | Сервер присылает `local:victim.mp3` или `file:private.mp3`. Зарезервированные локальные пространства имён отклоняются для серверных id и обложек. |
| **Неограниченные ведущие метаданные — средняя** | Короткий заголовок ID3 объявляет почти 256 МБ данных. До декодирования проверяются объявленные размеры ведущих ID3/FLAC: не более 16 МБ суммарно. Такой файл не становится завершённой загрузкой. |
| **Потеря прежнего состояния — средняя** | Повреждённую сессию или историю нельзя переименовать в резервную копию. Последующее сохранение блокируется и сообщает об ошибке. Неизвестные версии состояния также проверяются. |
| **Потеря пароля при отказе DPAPI — средняя** | Шифрование нового пароля завершается ошибкой. На Windows файл прежних настроек остаётся без изменений; пустой пароль вместо старого не записывается. |
| **Неполный каталог — средняя** | В странице полного обхода одна строка невалидна. Полный обход завершается ошибкой и не объявляет усечённый список полной библиотекой. Обычный обзор может показывать исправные строки страницы. |

Дополнительно:

- Индекс не забывает файлы лишь из-за временного отказа доступа или
  недоступного каталога. Известные симлинки и junction отклоняются,
  выходящие через них пути нельзя читать и удалять.
- Суммирование размеров защищено от переполнения. Служебные имена Windows,
  включая `COM¹`, `COM²` и `LPT³`, не используются для музыкальных файлов.
- Очистка миниатюр затрагивает только управляемые BEAT файлы с ожидаемыми
  именами; произвольные изображения в этой папке остаются на месте.
- Чтение миниатюры ограничивает фактические байты, даже если её размер
  изменился после проверки метаданных.
- Атомарная запись удаляет временный файл при ошибке только после его
  собственного успешного создания.
- Ошибки сохранения серверной библиотеки, индекса, истории и сессии доходят
  до интерфейса. Записи списка библиотеки не выполняются параллельно.
- При добавлении WebM обнаружено выделение памяти по длине из недоверенного
  заголовка. В [локальной копии Symphonia core](../vendor/symphonia-core/BEAT-PATCH.md)
  бинарные поля свыше 32 МБ отклоняются до выделения и чтения; отказ выделения
  возвращается как ошибка. Остальные файлы зависимости сохранены без изменений.

Старый общий `.beat-index.json` при первом запуске связывается с аккаунтом
в сохранённых настройках. Его прежнего владельца невозможно восстановить,
если настройки уже менялись раньше: сам старый формат не содержал владельца.

## Исправления поведения и производительности

- После очистки загрузок локальные треки остаются в интерфейсе;
  воспроизведение локального файла не прерывается.
- Перемотка и время на паузе не создают ложное прослушивание. Восстановление
  аудиовывода сохраняет признак уже посчитанного прослушивания.
- Локальные миниатюры учитывают полный путь и обновляются при пересканировании,
  поэтому смена папки или картинки не оставляет прежнюю обложку на экране.
- Большие сетки альбомов рисуют только видимые строки и запрашивают их обложки.
  Коллекции для интерфейса разделяются через `Arc`, без полного копирования
  на каждом кадре; ключи сортировки локальных файлов вычисляются один раз.
- Полный каталог ограничен 50 000 альбомов, 500 000 треков и 32 МБ метаданных.
  Длинные подписи ограничены 1 024 символами; поиск соблюдает запрошенный
  небольшой размер выдачи, даже если сервер его игнорирует.
- Сохранение сессии использует окно до 1 000 треков вокруг текущего,
  без предварительного копирования всей очереди. Внешние длинные очереди
  ограничиваются и при чтении.
- Для недоступного несохранённого трека показывается причина отсутствия
  подключения вместо незаметного прекращения запуска.
- Перемотка потокового трека переводит читатель в режим без ожидания сети и
  прерывает уже начавшееся ожидание; интерфейс не ждёт сетевой таймаут.
- README уточняет восстановление последнего трека и очереди: время внутри
  трека пока не сохраняется. Добавлен полный текст лицензии встроенного шрифта.

## Проверки

- 142 теста приложения: реальные локальные HTTP-ответы, недопустимые пути,
  Windows junction, повреждение/блокировка файлов состояния, изоляция
  аккаунтов, сохранность файлов, ограничения метаданных и сетка 5 000 альбомов.
- Форматирование, Clippy всех целей с `-D warnings`, ссылки документации.
- Отдельная проверка настоящих коротких WAV, MP3, FLAC, OGG/Vorbis, M4A, AAC и Opus
  тем же файловым декодером приложения: во всех случаях получены аудиосэмплы.
- Opus добавлен по запросу в ходе аудита: Ogg и WebM, моно и стерео,
  теги и встроенная обложка. Тесты проверяют служебные сэмплы короткого и
  длинного файла, перемотку и старт из незавершённого файла без ожидания конца.
- RustSec по полному Cargo.lock: известных уязвимостей не найдено;
  предупреждение о неподдерживаемом `ttf-parser` сохранено в [SECURITY](../SECURITY.md).
- Gitleaks: история Git и рабочие файлы проверены на секреты.
- Оптимизированный Windows x64 EXE проверяется на ASLR, high-entropy ASLR,
  DEP, GUI subsystem и отсутствие динамического Visual C++ runtime.

## Ограничения проверки

Нативные сценарии с реальными Bluetooth-устройствами и всеми аудиодрайверами
не воспроизводились. Проверка аудиосэмплов не является прослушиванием через
физическое устройство. Полное фаззинг-тестирование сторонних декодеров и
изоляция их процесса не выполнялись. Ограничение ведущих ID3/FLAC не покрывает
все возможные блоки метаданных внутри любых контейнеров.

Opus с числом каналов больше двух пока не поддерживается. Новые функции,
кроме отдельно запрошенной поддержки Opus, в рамках аудита не добавлялись.
